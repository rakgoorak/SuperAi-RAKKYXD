# CLI chat timeout diagnosis and fix

## Report

The app displayed “CLI ไม่ตอบกลับภายในเวลาที่กำหนด ตรวจบัญชีและการเชื่อมต่อใน Terminal แล้วลองส่งใหม่” during a long Codex task. The message was generated by `CliChatManager`, not evidence that Codex authentication itself failed.

## Reproduction

`node --import tsx --test packages/studio/test/cli-chat-timeout.test.ts`

The initial four deterministic fake-clock cases all failed on the old implementation:

1. A process continuously emitting answer updates was killed at the fixed total-turn deadline.
2. Partial JSON and valid protocol/reasoning activity did not clear the startup timer, because no visible parsed update was produced.
3. A stalled turn reported a generic account/connection message and unfinished tools could become “done”.
4. Both startup and total-turn timers could issue a kill for the same silent process before `close` arrived.

The tests use an injected fake process without a PID and Node's fake timers. They make no real provider requests, do not kill a real CLI, and do not read credentials.

## Hypotheses and evidence

- Fixed total-duration timeout: confirmed in source (`turn: 600000`) and by active-output reproduction.
- Startup timeout despite protocol output: confirmed by partial JSON and hidden reasoning reproduction. The old implementation cleared startup only for parsed visible updates.
- Genuine login/network failure: still possible for the user's live provider, but not established by this screenshot or the synthetic tests. No live account claim is made.

## Fix

- Retain the 90-second startup limit for a process that sends no data.
- Treat the existing ten-minute `turn` limit as maximum silence, resetting it on stdout or stderr activity, including partial/unrecognized JSON.
- Remove the total-turn timer. Long-running work can continue while emitting data; the user's Stop control remains available.
- Terminate once, retain ownership until child `close`, and report startup silence separately from stalled activity.
- Mark unfinished tools failed on timeout/process failure instead of presenting them as successfully completed.

## Validation

The final focused run passed **21 tests** across `cli-chat-timeout.test.ts`, `cli-chat.test.ts` and `chat-settings.test.ts`. The Studio TypeScript production build passed. Coverage includes continuous activity beyond the former total limit, partial/hidden protocol events, stderr progress, silent startup, silence after progress, cancellation, process-close ownership and existing session/auth flows.

This confirms the application timer defects and the source fix; it does not establish the health of the user's real CLI credentials or network. The already prepared v1.0.20 ZIP/installer precede this new source fix and must be repackaged before publication.
