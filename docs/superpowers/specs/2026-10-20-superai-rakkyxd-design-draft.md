# SuperAi & RAKKYXD — แบบเสนอเพื่อทบทวน

สถานะ: ผู้ใช้อนุมัติและให้เริ่มพัฒนาแล้ว รวมข้อกำหนด OpenCode และ Freebuff หนึ่ง managed session

## เป้าหมาย

พัฒนาแอป Windows ภาษาไทยที่มีรูปแบบการทำงานอ้างอิง BridgeMind โดยใช้แบรนด์ SuperAi & RAKKYXD และโปรแกรมคู่หู SuperAi Voice & RAKKYXD สำหรับพูดเพื่อพิมพ์ ปรับปรุงจาก Electron, React และ Studio Server ที่มีอยู่ ไม่อ้างว่าเข้าถึง source code หรือระบบภายในของ BridgeMind

## แนวทางที่เสนอ

1. แนะนำ: ต่อเติม Electron เดิม แยกบริการ terminal, browser, agent และเสียงให้ชัดเจน ใช้ WebContentsView แสดงเว็บไซต์ภายในหน้าต่างจริง ใช้เวลาปรับโครงสร้างแต่ทดสอบแต่ละส่วนได้
2. ปรับเฉพาะหน้าตา: ทำได้เร็ว แต่ไม่บรรลุความต้องการ browser และการทำงานของ agent อย่างครบถ้วน
3. เขียนใหม่ทั้งหมด: จัดโครงสร้างได้อิสระ แต่เพิ่มความเสี่ยงและต้องทำระบบ terminal และ workspace ใหม่

## หน้าจอและภาษา

- โทนกราไฟต์ดำ ตัวอักษรไทยอ่านง่าย ใช้สีฟ้าและเขียวเน้นสถานะ ลดแสงเรืองและข้อมูลตกแต่ง
- แถบซ้าย: โปรเจกต์ งานสนทนา เพิ่ม/เปลี่ยนชื่อ/ลบ และสถานะจากระบบจริง
- แถบบน: แบรนด์ สลับ ผู้ช่วย / โค้ด / สนทนา สร้างงาน Preview และการตั้งค่า
- พื้นที่กลาง: terminal แบบแท็บ/แบ่งช่อง เลือกเป้าหมายส่งคำสั่ง สั่งหยุด และแสดงสถานะเชื่อมต่อ
- ด้านขวา: browser ภายใน มี URL ย้อนกลับ ถัดไป รีโหลด แท็บ ปิด และเปิดภายนอก ปรับขนาดได้
- ช่องคำสั่ง: พิมพ์หรือรับข้อความจากเสียง ส่งเฉพาะงานหรือทุกช่อง ต้องแสดงเป้าหมายชัดเจน
- ไม่มีตัวเลข model/version งานสำเร็จ หรือสถานะบัญชีสมมติ

## ระบบหลัก

- Desktop main process ดูแล lifecycle, browser views และ IPC ที่ตรวจสอบต้นทางและพารามิเตอร์
- Studio API ดูแล workspace, session, CLI availability และข้อผิดพลาด โดย bind เฉพาะเครื่องนี้และตรวจสอบสิทธิ์ของ desktop client
- Terminal session มี cwd และ workspace เจ้าของชัดเจน การสลับโปรเจกต์ต้องไม่ส่งคำสั่งไปโปรเจกต์เดิมโดยเงียบ
- ตรวจ CLI ที่ติดตั้งก่อนเปิด เริ่มจาก Claude Code, Codex, Gemini CLI และ terminal ปกติ ตัวเลือกอื่นเพิ่มได้เมื่อมี adapter และทดสอบจริง
- ใช้ sign-in ของ CLI แต่ละราย ไม่ดึง cookie ของเว็บไซต์มาอ้างว่าเป็นการเข้าสู่ระบบ CLI
- สถานะ API/terminal แสดง loading, success, error และทางลองใหม่ ไม่มี catch เงียบสำหรับงานของผู้ใช้
- เก็บ workspace, thread และการตั้งค่าในโฟลเดอร์ข้อมูลของแอป พร้อม migration จากข้อมูลเดิม ไม่เก็บ process id เป็นหลักฐานว่า session ยังทำงานหลัง restart

## Preview

- ใช้ Chromium ของ Electron ผ่าน WebContentsView แทน iframe ใน desktop
- รองรับ http/https และ localhost การค้นหาบนเว็บต้องแยกจากการเปิด URL
- จัดการ navigation, resize, popup, download, load failure และซ่อน view เมื่อเปิด modal
- ไม่ใส่ Node integration หรือ privileged preload ให้เว็บไซต์ภายนอก
- กรณีเว็บไซต์จำกัด embedded browser หรือจำเป็นต้องใช้ browser ภายนอก ให้แสดงเหตุผลและเปิดภายนอกได้ ไม่รับรองว่าเว็บไซต์ทุกแห่งอนุญาตการใช้งานในแอป
- เมื่อเปิด UI ผ่านเว็บ browser ปกติ ต้องแสดงความสามารถที่รองรับจริงและข้อจำกัดของ iframe

## SuperAi Voice & RAKKYXD

- แอปแยก เปิด/ปิดได้เอง มี tray และหน้าต่างเล็ก เลือกไมโครโฟน ภาษาไทย/อังกฤษ และปุ่มลัดระดับระบบ
- แนวทางแนะนำ: transcription บนเครื่องด้วย Whisper รุ่น multilingual ต้องดาวน์โหลด model ครั้งแรกและมีหน้าจอแสดงความพร้อม ขนาดและความเร็วขึ้นกับ model/เครื่อง
- กดปุ่มลัดเริ่ม/หยุดอัด ถอดข้อความ แล้วใส่ลงช่องคำสั่ง SuperAi ที่เลือก โดยไม่ส่งคำสั่งอัตโนมัติ
- การพิมพ์ไปโปรแกรมอื่นบน Windows ต้องจับหน้าต่างเป้าหมายก่อนเริ่มอัด และใช้ช่องทาง native ที่ทดสอบกับ Unicode ภาษาไทย ไม่ยิงข้อความไปหน้าต่างที่เพิ่งสลับเข้ามา
- หากเป้าหมายไม่มีช่องกรอก/มีสิทธิ์สูงกว่า/ปฏิเสธการแทรก ให้เก็บข้อความและให้คัดลอกได้ ไม่อ้างว่าส่งสำเร็จ
- แจ้งไมค์ไม่พร้อม ไม่มี model และ transcription ล้มเหลวเป็นภาษาไทย พร้อมยกเลิกและลองใหม่
- ไม่ใช้การพบคำว่า ส่ง/รัน ในข้อความทั่วไปเป็นเหตุให้ execute คำสั่ง

## ลำดับส่งมอบ

1. แอปหลัก: แก้ startup/build และสถานะ session, UI ไทย, terminal/CLI, workspace, settings และ browser Preview จริง
2. โหมดสนทนา/ผู้ช่วย: เชื่อม backend จริง แสดง progress, cancel และผลลัพธ์ พร้อมจัดเก็บประวัติ ทดสอบการแยกจาก terminal
3. โปรแกรมเสียงแยก: recording/transcription, hotkey, เชื่อมช่องคำสั่ง และการแทรกข้อความบน Windows
4. ทดสอบรวมและแพ็กโปรแกรม: ปุ่มและเส้นทางใช้งานตามรายการ พร้อมเอกสารวิธีติดตั้งและข้อจำกัดที่พบ

## เกณฑ์ตรวจรับ

- Build และ automated tests ผ่าน บันทึกผลจริง ไม่ใช้ echo แทนการทดสอบ
- ทดสอบสร้าง/เลือก/แก้ไข/ลบโปรเจกต์ เปิด/ส่ง/หยุด/ปิด CLI และ terminal แยกโปรเจกต์ รวมทั้ง restart
- ทดสอบ browser localhost และเว็บภายนอก การนำทาง แท็บ resize modal และ URL ที่เปิดไม่ได้
- ทดสอบปุ่มทุกตัวในหน้าจอที่ส่งมอบ บันทึกว่าใช้งานจริงหรือ disabled พร้อมเหตุผล ไม่มีปุ่มหลอก
- ทดสอบเสียงภาษาไทยจริงด้วยไมโครโฟนและหน้าต่างเป้าหมาย รวมกรณียกเลิกและไม่มี model
- กรณีต้องใช้บัญชี/ไมโครโฟนของผู้ใช้ ให้ระบุขั้นตอนที่ต้องให้ผู้ใช้ทดสอบ ไม่ถือว่า verified โดยไม่เคยทดสอบ
- เป้าหมายคือผ่านกรณีตรวจรับและจัดการข้อผิดพลาดอย่างชัดเจน ไม่รับรองว่าไม่มี error ในทุกสภาพแวดล้อม
